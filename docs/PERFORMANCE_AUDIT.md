# 全量性能审计与第三轮优化

2026-09-09。静态扫描覆盖 `internal`、`cmd`、`catalog` 全部 121 个生产 Go 文件（36,132 行），并检查两份 HTML 界面及签名 JavaScript。逐文件疑似开销位置见 [performance-inventory.json](performance-inventory.json)，可用 `python scripts/performance_inventory.py` 更新。匹配结果是审查线索，不代表每处都是性能缺陷。动态验证使用代表性协议、请求与模拟上游，不代表 93 个来源均做过真实账号性能测试。

## 本轮实测修改

Windows amd64、i9-14900KF、Go 1.27.1；同场景基准各运行三次，每次 300 ms，表中取中位数。时间和分配量只适用于这些基准。

| 场景 | 修改前 | 修改后 | 改动 |
|---|---:|---:|---|
| 1,000 行 SSE data 合并 | 2.913 ms；14,224,234 B；约 1,000 次分配 | 15.237 µs；40,961 B；1 次分配 | 多次追加复用单个缓冲区，避免二次方复制 |
| 100 行 SSE data 合并 | 28.246 µs；145,410 B；99 次 | 1.489 µs；3,456 B；1 次 | 同上 |
| 约 8 KiB JSON 路由检查 | 6.012 µs；96 B；4 次 | 2.903 µs；48 B；1 次 | 常见键直接匹配；引号扫描使用 bytes.IndexByte |
| 1 KiB 分块请求，4 MiB 上限 | 201.709 µs；4,202,569 B；3 次 | 1.684 µs；4,144 B；2 次 | 从 4 KiB 开始按需增长，容量限制在请求上限加一 |

单行 SSE 保持零分配（16.8→17.16 ns，视为测量波动）。多行合并不修改输入；转义路由键仍回退到 JSON 解码。JSON 完整合法性验证保留。CPU profile 指出原字符串扫描占约 47.6%；修改后完整 JSON 校验约占 69.8%，不为减少该开销而省略校验。

九组来源 HTTP 客户端的空闲连接数从总计 8、单主机 4，改为按 `MaxInflight` 保留 4–256 条，沿用 60 秒空闲超时。它提高连接复用机会，也增加空闲连接资源保留；不会主动建立这些连接，不提高账号并发授权。通用适配器上一轮的双波次连接复用测试仍通过。

## 检查范围与处理决定

| 区域 | 检查项与结论 |
|---|---|
| API 入口 | 请求体预分配、重复解析、鉴权、错误响应；修复分块请求过量分配，保留恒定时间鉴权、大小限制和原有内存配额预留 |
| 协议 | JSON 扫描、SSE 拼接、转换与缓冲；修复上述热路径，保留重复键和转义处理、终止帧与 EOF 校验 |
| 调度 | 锁、候选扫描、通知分配、排队、计时器；复核上一轮优化，保留公平轮转、等待者唤醒和配额约束；全部候选正分时仍需扫描 |
| HTTP 来源 | 客户端复用、连接池、读取、JSON 编解码、超时和取消；统一九组小连接池，保留有界读取和源协议完成判断 |
| 浏览器来源 | Chrome 生命周期、账号串行化、轮询、页面求值与会话持久化；未移除账号隔离、轮询节奏及发送前 dirty 状态落盘，这些涉及正确性和恢复保证 |
| 配置、密钥与持久化 | 文件访问、序列化、锁、fsync；启动/管理路径频率较低，缺少热路径证据时保留耐久性保障 |
| 界面与辅助命令 | HTML 刷新、请求、渲染及签名 JS；静态检查未形成可测量的本轮改动，未声称完成真实浏览器长时 profiling |

部分私有协议适配器仍缓冲完整回复再输出，以确认来源完成状态。这会增加首字延迟；改变它需要逐来源验证中断、错误和完成语义，不能简单删除缓冲或宣称已经实现真实流式。

## 验证及边界

- Windows `go test ./...`、`go vet ./...` 通过。
- Linux 全量 `go test -race ./...` 通过；最后调整请求体读取后再次运行 API/协议 race 测试通过。
- JSON 检查 fuzz 运行 10 秒，完成 1,662,244 次执行，无失败。
- 增加 SSE 输入不变、转义路由键、请求体边界、跨 4 KiB 增长、容量上限与无进展读取回归测试。
- 模拟端到端测试：100 并发、30,000 请求、每块 1 ms 延迟，直连和网关均零错误。该同进程短测不用于证明生产容量或稳定吞吐提升。

尚未完成真实 93 来源逐一 profiling、独立负载机容量测试、长时间 RSS/CPU 稳态测试和慢客户端持续压测。扫描已覆盖生产代码，但不意味着所有性能开销都已消除。复现微基准：`go test ./internal/api ./internal/protocol -run '^$' -bench 'Benchmark(ChunkedSmallBody|Inspect|SSEData)' -benchmem -benchtime=300ms -count=3`。
