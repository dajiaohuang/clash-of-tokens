# Clash of Tokens：下一版完整开发清单

**以 `8387d509` 审计为基线，保留已经完成的架构，集中修复断点、补齐完整操作流程，并统一验收。** 不再按“新增了几个页面、注册了几个 Provider”判断完成。

**交付目标：**

> 用户从前端完成来源配置、账密导入、正常登录、会话绑定、模型调用、凭证续期、启停、分组、调度调整和状态观察；重启后恢复；整个过程不需要维护者手改 JSON 或临时补环境变量。



文件包含 **92 项可勾选任务、28 项端到端验收场景、六个审计问题的关闭条件，以及原 51 项要求的逐项映射**。下面列出完整交付范围与关键验收要求。

## 1. 统一凭证解析，消除“配置成功、运行失败”

当前最先要修的是：中央配置接受 `CredentialRef`，但部分 `majorweb` Adapter 仍先要求 `KeyEnv` 非空，导致合法配置无法执行。

- [ ] **修复 `CredentialRef-only` 路径。** 不设置 `KeyEnv`，仅使用受保护凭证引用，也能通过真实 Adapter 发起调用。
- [ ] **所有 Adapter 使用统一 resolver。** 环境变量、vault、外部密码管理器引用进入同一个解析流程；清除各 Adapter 私自读取文件、临时设置环境变量等旁路。
- [ ] **固定继承与覆盖规则。** Account 默认值、Source 覆盖、旧 `KeyEnv` 的优先级明确；显式引用失效时，不得偷偷换用另一份凭证。
- [ ] **区分登录材料和调用凭证。** 用户名密码、API Key、Cookie、OAuth Token、浏览器 Profile、设备会话不能互相冒充。
- [ ] **统一错误和版本。** 缺失、锁定、过期、类型错误、撤销、需要交互授权分别返回明确状态；凭证或账号身份变化使旧验证证据过期。

**验收：** 通过“真实 Adapter factory＋合成 resolver＋本地 mock 上游”测试，不仅测试凭证字符串能否读取。

## 2. 完成账密导入与密码管理器集成

所有导入方式统一经过：

```text
选择来源 → 解析 → 脱敏预览 → 勾选条目
→ 匹配 Provider → 选择账号 → 校验 → 保存引用 → 验证
```

| 导入范围 | 本轮必须交付 |
|---|---|
| 浏览器导出 | Chrome、Edge、Brave、Firefox、Opera、Vivaldi、Chromium、Arc，以及平台适用的 Safari／Apple Passwords／Google Password Manager，按**实际导出格式和版本**建立支持矩阵 |
| 密码管理器文件 | Bitwarden、1Password、KeePass／KeePassXC、Proton Pass、Dashlane、NordPass、LastPass、Enpass，逐项验证承诺支持的格式 |
| 官方集成 | 补充 1Password、Bitwarden 的可选集成，只读取用户授权选定的条目与字段 |
| 环境变量和已有配置 | 支持显式选定、预览、绑定；配置仍保存引用，不复制到普通配置文件 |
| 手动输入 | 支持 API Key、登录材料、Cookie、Token 等声明的类型，由 Provider 契约决定用途 |

1Password 提供桌面应用与 CLI 的授权集成；Bitwarden CLI 也有独立的解锁会话机制。应接这些授权路径，而不是自行逆向整个密码库。

必须补齐：

- [ ] **选择式导入。** 未勾选条目不持久化，不自动登录，不自动调用模型。
- [ ] **重复和冲突处理。** 支持保留、替换、新建；不按相同邮箱自动合并不同产品账号。
- [ ] **精确匹配。** 校验主机名、租户、类型和来源；相似域名不能触发凭证绑定。
- [ ] **有界解析。** 限制文件大小、记录数、字段长度、解析时间、预览保留时间，覆盖错误 CSV／JSON 等输入。
- [ ] **秘密不回显。** 密码、Cookie、Token 不进入预览响应、日志、URL、浏览器持久存储和诊断包。
- [ ] **支持类型真实。** “能解析导出文件”“能连接官方管理器”“能导入浏览器会话”分别显示，不用一个“已支持”覆盖。

**验收：** 导入 100 条合成记录、只选两条，只保存两条；绑定后可以调用对应 mock Source；取消导入不产生持久化和上游请求。

## 3. 打通“导入／登录 → 可调用 → 续期”的完整链路

这是当前最大的功能缺口：登录材料导入、浏览器认证检查和生成阶段所需凭证尚未完全衔接；OAuth／CLI 的自动续期也仍有缺口。

- [ ] **扩展 Descriptor 的认证契约：**

  ```text
  login_materials
  invoke_credentials
  login_flow
  session_acquisition
  refresh_strategy
  allowed_origins
  ```

- [ ] **完成正常登录向导。** 选择账号和 Profile、打开登录页、等待用户授权、确认身份、绑定会话、保存、最小生成验证。
- [ ] **覆盖两种执行路径。** 原生 HTTP 来源取得实际需要的调用凭证；浏览器执行来源绑定受控 Profile。不能仅检测“网页已登录”就宣布两种方式都可调用。
- [ ] **处理账号错配。** 当前登录账号、租户与目标 Account 不一致时阻止误绑定；共用 Profile 切换身份时显示影响对象。
- [ ] **完成 OAuth 生命周期。** 在上游正常支持的范围内管理访问 Token、刷新 Token、有效期、scope、账号标识和轮换；不支持自动刷新的明确进入重新授权状态。
- [ ] **刷新协调。** 同账号并发只进行一次刷新；旧刷新结果不能覆盖新凭证，刷新失败不能无限循环。
- [ ] **处理解绑、撤销、重启。** 本地删除与上游撤销分别显示；重启恢复绑定，过期时给出正确操作入口。

前端分别显示：

```text
材料已导入
登录已确认
调用凭证／执行会话已就绪
生成验证通过
凭证有效期／需要重新授权
```

**验收：** API Key、浏览器原位执行、浏览器登录后 HTTP 调用、OAuth／订阅、设备会话五条架构路径，分别完成生命周期测试。不能用其中一条通过代表全部。

## 4. 浏览器与设备支持做到“界面承诺等于实际能力”

- [ ] **按操作标注支持。** 安装发现、启动、连接、登录、会话导入、生成、停止分别记录。
- [ ] **Chromium 系完善 CDP 路径。** 默认使用隔离用户数据目录，不假定能直接调试用户日常默认 Profile。Chrome 对默认数据目录的远程调试已有明确限制。
- [ ] **Firefox 完成 BiDi 路径。** 不再把 Firefox 启动后交给 `chromedp`。Firefox 已移除 CDP，实现和前端声明必须同步。未完成时应阻止不支持的操作，但任务仍算未完成。
- [ ] **Profile 资源隔离。** 管理目录锁、进程归属、端口、账号绑定；不同账号不争用同一登录环境。
- [ ] **进程生命周期完整。** 启动、人工关闭、崩溃、停止、网关重启后的校对都经过测试；只停止本项目拥有的进程树。
- [ ] **会话范围准确。** 只绑定用户授权的必要会话；共享 SSO Cookie 涉及多个产品时明确告知实际范围，不能虚假保证按产品完全隔离。
- [ ] **设备路径闭环。** doctor、前台检查、账号状态、单设备租约、聊天提交、回答完成、取消和断连恢复全部可见。

**验收：** 每个声明支持的浏览器与系统组合，执行真实引擎测试；不能靠“检测到可执行文件”算通过。设备只执行聊天模拟，不增加下单、支付等业务操作。

## 5. 管理长任务异步化，配置事务与热更新补齐

上轮实际测试已复现：慢验证持有控制面全局锁，连带阻塞 `/admin/status`。这是必须关闭的确定问题。

- [ ] **移除长操作持锁。** 网络验证、登录等待、密码管理器授权、模型发现不持有配置提交锁。
- [ ] **建立有界管理 Job。** 返回 `202 + job_id`，提供进度、事件、取消、超时和结果；不扩展成 Agent 编排系统。
- [ ] **防止旧结果覆盖新配置。** Job 记录相关实体与版本，提交结果时重验账号、凭证和 Profile；失效结果标为 `stale`。
- [ ] **同资源互斥、不同资源并行。** 同账号刷新、同 Profile 登录、同设备交互协调执行，不用全局锁串行全部管理操作。
- [ ] **配置失败可恢复。** 覆盖校验失败、prepare 失败、磁盘满、写入失败、进程中断，不提前报告成功。
- [ ] **处理 vault 与配置的一致性。** 使用凭证版本暂存、引用提交、失败补偿和孤儿清理，不假装两个存储天然具备原子事务。
- [ ] **热更新保持配额计数。** 新 generation 不能把全局、账号和共享配额域的在途计数清零。
- [ ] **禁用语义严格。** 禁用提交成功后不再提交新上游请求；在途默认 drain，立即终止是单独操作。
- [ ] **显示实际生效版本。** 区分期望配置、当前生效配置和待重启字段；多标签页冲突不能静默覆盖。

**验收：** 一个验证任务等待 5 秒时，状态、取消和禁用操作仍及时响应；验证过程中更换账号或凭证，旧结果不能把新账号标为已验证。

## 6. 前端全面验收，不再只检查“页面存在”

所有入口调用同一套管理服务，列表、详情、搜索结果中的同名操作不得出现不同的校验和保存行为。

| 页面 | 必须完整跑通的操作 |
|---|---|
| **Overview／Activity** | 实时状态、排队、请求结果、认证问题、管理 Job、资源占用、最后更新时间 |
| **Providers** | 类型与能力筛选、详情、启停、Auto 批准、添加账号、批量验证 |
| **Accounts** | 多账号、导入／登录、换凭证、启停／Auto、权重、容量、配额域、继承配置、删除 |
| **Credentials** | 手填／导入／外部引用、脱敏预览、替换、重导、影响对象、解绑、删除、vault 状态 |
| **Sources／Models** | 来源绑定、模型发现／手填、协议与能力、别名、评级、批量启停、分组 |
| **Groups／Auto** | 多组成员、批量加入移出、拖拽与键盘排序、策略、硬限制与偏好 |
| **Routing／Quota／Pools** | 模拟与排除原因、账号池策略、共享域、容量、冷却、支出限制 |
| **Browsers／Devices** | 环境检查、Profile 绑定、启动／停止、登录进度、验证、取消和失败处理 |
| **Sessions／Health** | 会话元数据、局部清理、支持范围、验证证据、过期状态、重新认证 |
| **Config／History／System** | 全部配置编辑、预览、diff、提交、回滚、迁移、待重启、版本、诊断和脱敏导出 |

同时补齐：

- [ ] **配置和运行状态分开刷新。** 不周期性重拉全部目录、schema 和历史。
- [ ] **不覆盖未保存编辑。** 保留焦点、选择、排序和滚动位置。
- [ ] **隐藏标签页降频。** 断线重连、事件恢复、错误和陈旧状态可见。
- [ ] **大表与全局搜索可用。** 分页或虚拟化、中文筛选、键盘操作和批量编辑。
- [ ] **所有敏感操作有影响预览。** 取消后不写配置、不执行上游操作。
- [ ] **测试台按有效协议工作。** 不能把仅支持其他协议的模型放进固定 Chat 请求路径后报错。
- [ ] **首次启动流程完整。** 从空配置走到第一次调用，全程前端操作。

当前审计指出的“状态主要是快照、UI 回归未进入 CI”，要通过实际页面流程关闭，而不是再加一组静态页面断言。

## 7. 路由、流式和会话：保留已有能力，补全回归

这一包以**不回归和扩大边界测试**为主，不重新设计已经实现的 fallback。

- [ ] **八类开关全部验收。** Provider、Account、Source、Model 各自的 `enabled` 和 `auto_approved`，分别从页面影响真实请求。
- [ ] **组成员不等于调用资格。** 加入组不能自动提升质量等级、增加工具能力或覆盖上级禁用。
- [ ] **显式调用与 Auto 遵守共同边界。** 显式调用可以不要求 Auto 批准，但不能绕过禁用、认证和全局安全限制。
- [ ] **模拟器复用真实资格逻辑。** 返回采样版本和排除原因；实时状态改变时不承诺最终必选同一来源。
- [ ] **安全重试完整。** 总 deadline、尝试次数、冷却、共享额度、重复候选排除一致；已输出或提交状态未知不重放。
- [ ] **各协议分别判断完成。** Chat、Responses、Messages、Gemini 都覆盖正常结束、拒绝、长度终止、工具调用、错误和断流。
- [ ] **会话不串用。** 相同本地 API Key 下不同会话不能被合并到同一上游房间；改组、换账号不能转发错误的会话 ID。
- [ ] **能力如实声明。** `chat-only / native-tools / emulated-tools / vision / multi-turn / buffered` 分别标记；不执行 Agent 工具。
- [ ] **聚合 API 约束不丢失。** 严格来源限制能够下传才允许使用；避免两层重试放大和 BYOK 额度重复计算。

**验收：** 原来已经通过的限流换源、错误流和位置／费用语义测试继续通过；新增认证与热更新不破坏这些行为。

## 8. 所有 Provider 建立统一合约和验证矩阵

- [ ] **Descriptor 为共同事实来源。** 工厂、配置、凭证需求、协议、能力、管理操作和 UI schema 保持一致。
- [ ] **全部可执行 Adapter 有离线契约测试。** 必须经过实际工厂和协议实现，不能只测试空壳路由返回 200。
- [ ] **模型发现纳入管理 Job。** 新发现模型默认未批准、未评级，不自动进入 Auto。
- [ ] **模型身份与评价分开。** 上游显示名、实际返回模型、规范身份、评级及验证证据独立。
- [ ] **Session 管理能力明确。** 哪些来源支持列出、过期、清理、取消逐项声明，不支持就明确说明。
- [ ] **真实验证绑定版本。** Provider、Adapter、账号、凭证、Profile、模型和协议变更，使相应证据过期。
- [ ] **未实现与未验证不得混淆。** 目录可以完整，但普通模型列表不能把研究条目伪装成可调用来源。

**验收：** 可执行 Adapter 的离线合约覆盖率达到 100%；真实上游验证单独统计，缺账号或设备明确标为阻塞，不能用 mock 补成 live 成功。

## 9. 跨平台凭证存储与秘密安全

macOS 必须针对**真正分发的二进制**修复：上轮存在原生 Keychain 测试通过、上传产物却使用不支持该功能的构建配置的问题。

- [ ] **macOS 最终产物完成 vault 生命周期测试。** 新增、重启读取、更新、删除。
- [ ] **Windows、Linux 同样测试发行产物。** 无可用存储、锁定、授权拒绝明确失败，不静默落明文。
- [ ] **秘密不进入普通配置与日志。** 包括 journal、导出、诊断、URL、命令行和前端持久存储。
- [ ] **全链路合成秘密测试。** 将 canary 放入密码、Token、Cookie 和上游错误，检查所有输出；不能仅依赖 `Secret.String()`。
- [ ] **凭证目的地受控。** 修改 Base URL、租户或登录 origin 时重新确认，防止把已绑定密钥发送到其他端点。
- [ ] **管理与模型调用权限隔离。** Job、状态事件和凭证接口同样鉴权；验证 Host、Origin、CSRF 和本机访问边界。
- [ ] **备份恢复规则明确。** 普通配置导出不带秘密；恢复后缺失引用提示重绑定；回滚不能复活已撤销凭证。
- [ ] **发布依赖可追踪。** 版本、校验和、第三方许可、依赖锁定和漏洞检查齐备。

## 10. 性能验收按你的真实使用场景执行

以下是**验收目标与测试条件，不是已经达到的成绩**。

| 场景 | 验收要求 |
|---|---|
| 100+ 来源全部禁用 | 不启动专属探测、浏览器、设备任务或后台 worker |
| 32／128／512／1000 mock 流 | 报告 CPU、RSS、GC、FD、goroutine、吞吐、排队和尾延迟 |
| 1／8／16 MiB 输入 | 按请求体总字节预算准入，不靠无限排队或 OOM 限流 |
| 5 秒来源验证并行状态／禁用 | 固定回环环境管理操作 p99 目标不超过 200 ms，不随验证一起等待 |
| 连续 100 次热更新 | 不清零共享容量，不遗留旧 generation、连接和租约 |
| 慢客户端＋取消＋429＋凭证轮换 | 背压、状态计数、释放和错误归属正确 |
| 24 小时混合稳态 | 没有持续增长的队列、会话、FD、goroutine、Job 或浏览器进程 |
| 多个前端标签页 | 隐藏页降频，事件订阅有界，不反复传完整目录和历史 |

**同时报告 Core 与浏览器／设备／可选导入工具的资源占用。** 不只展示 Go Core 很轻，隐藏其他进程的成本。

## 11. CI 必须从“代码测试”升级到“最终产品验收”

- [ ] **PR 必跑：** Go 单元与契约测试、race、vet、解析器和导入器边界测试、秘密检查。
- [ ] **前端回归接真实 Go 后端。** 浏览器实际点击，调用真实 Admin API，后面接合成 vault 和本地 mock 模型。
- [ ] **不能把主要 Admin API 全部 mock 为成功。**
- [ ] **浏览器驱动测试使用实际引擎。** 本地合成登录站点验证流程，真实 Provider 登录另行验收。
- [ ] **最终打包产物测试。** 不是测试一种构建方式，再发布另一种。
- [ ] **真实秘密与公共 PR 隔离。** 用户授权的真实测试在受控环境执行，频率和费用有限。
- [ ] **结果记录确切版本。** commit、artifact hash、平台、案例、结果、证据和阻塞原因。

## 12. 最终发布必须通过的端到端流程

完整文件已经列出 28 个案例。以下十组不能缺：

| 流程 | 必须证明 |
|---|---|
| **空配置 → 前端添加来源 → 调用** | 不手改 JSON、不补隐藏环境变量即可使用 |
| **导入 → 选账号 → 绑定 → 调用** | 导入凭证真正被对应 Adapter 使用 |
| **浏览器登录 → 会话绑定 → 生成 → 重启** | “登录成功”与“可调用”两阶段都成立 |
| **凭证到期 → 刷新／重新授权** | 无无限重试，无过期状态假成功 |
| **两个账号＋多个会话并行** | 不串账号、会话、额度和验证证据 |
| **八类开关＋多组成员＋策略排序** | 页面、持久配置、模拟器和真实调度一致 |
| **慢验证＋换凭证＋取消＋禁用** | 控制面不阻塞，旧结果不能覆盖新账号状态 |
| **错误流＋安全 fallback＋客户端取消** | 不拼接回答、不重复未知提交、不误记成功 |
| **配置冲突＋磁盘失败＋升级回滚** | 不丢更新，不损坏引用，不复活撤销秘密 |
| **跨平台发行＋混合长稳态** | 下载到的程序具备文档承诺能力，长期资源有界 |

### 固定交付顺序

```text
统一凭证契约与基线回归
            ↓
并行修复：
控制面 Job / 平台 vault 产物 / 浏览器协议 / 导入器
            ↓
登录—调用—续期闭环
            ↓
完整前端联调、全 Provider 合约
            ↓
真实授权验证、最终产物测试、混合稳态
            ↓
对照原 51 项与六个审计发现发布验收报告
```

可以拆多个可评审 PR，但这是**同一套版本交付目标**，不再以“先把按钮补上，其他以后再说”作为完成。

**最终完成标准：不是 92 个框被勾上，而是每个框都有实现、测试和证据；用户能从前端把来源真正配置成可调用、可续期、可调度、可观察的 Provider。**
